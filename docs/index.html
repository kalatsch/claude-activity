claude-activity

A local heatmap of your Claude Code and Codex CLI usage — when you actually worked, by hour × day, with token totals and estimated API cost. Everything runs on your machine; no server, no telemetry.

Claude Code Codex CLI work / off / weekend split daily tokens & API cost persistent history
Install

Install from this repo

Inside Claude Code — no central publishing involved. These are two separate slash commands: run them one at a time, in order.

1Add this GitHub repo as a plugin source
/plugin marketplace add kalatsch/claude-activity
2Install the plugin from it
/plugin install claude-activity@claude-activity

Update to the latest version

When a new version ships — refresh the source, then update the plugin. Run them one at a time, in order.

1Refresh the marketplace source
/plugin marketplace update claude-activity
2Update the plugin
/plugin update claude-activity@claude-activity

↻Prefer clicks? The built-in /plugin menu → Manage plugins → claude-activity → Update does the same. Either way, restart the window or run /reload-plugins to load the new version into the current session.

After install

Usage

  • /activity — generate & open
  • /activity --settings — work days, hours, gap…
  • /activity --help — all flags
  • /activity --no-open — silent run

Requirements

  • Python 3.9+ — no external packages
  • A modern browser (opens from file://)
  • Reads ~/.claude/projects & ~/.codex/sessions
  • Writes only to ~/.claude-activity
Settings

The first-run wizard (re-run anytime with /activity --settings) asks for these four. They're saved to ~/.claude-activity/config.json and apply on the next /activity run (your history is preserved).

gap_minutes10
Longest pause between two actions that still counts as continuous work. Time is summed only across events closer together than this. Lower (e.g. 5) is stricter — ignores short idle, so less total time; higher (e.g. 30) is lenient — bridges longer breaks, so more total time. This single number defines how “time worked” is measured.
work_intervals[[9, 18]]
Which hours of a work day count as working hours — a list of [start, end) pairs (0–23, end excluded). Inside the window → work (green); outside → off-hours (yellow). Use two ranges to carve out lunch, e.g. [[9, 13], [14, 18]].
work_days[0, 1, 2, 3, 4]
Which weekdays are work days — 0=Mon … 6=Sun. Listed days are split into work / off-hours by work_intervals; any day not listed renders entirely as weekend (red).
first_day_of_week0
Only the column order of the “By day of week” chart. 0=Monday (ISO), 6=Sunday (US). Does not change any totals or colors.
